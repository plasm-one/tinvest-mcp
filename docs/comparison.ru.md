# T-Invest MCP от Т-Банка и tinvest-mcp: сравнение MCP-серверов Т-Инвестиций

У Т-Банка есть официальный MCP-сервер Т-Инвестиций — **T-Invest MCP**
(<https://developer.tbank.ru/invest/mcp>). С его помощью ИИ-агента — Claude Code,
Cursor, Qwen Code, Gemini CLI или VS Code — можно подключить к брокерскому счёту.

**tinvest-mcp** решает ту же задачу, но иначе: это неофициальный сервер с
открытым кодом, который работает на вашем компьютере. Ниже — чем они
отличаются и в каких случаях лучше выбрать официальный.

Сразу оговоримся: мы не беспристрастны, tinvest-mcp написали мы. Поэтому всё
здесь можно проверить. Сведения об официальном сервере взяты из его публичной
документации, а про наш сервер мы указываем, в каком файле что реализовано.

## Главное в одной таблице

| | **tinvest-mcp** | **T-Invest MCP (Т-Банк)** |
|---|---|---|
| Где работает | на вашем компьютере | на серверах Т-Банка |
| Транспорт | stdio, без открытых портов | streamable HTTP |
| Адрес | — | `https://invest-public-api.tbank.ru/mcp` |
| Где хранится токен | в файле `.env` | в настройках MCP-клиента |
| Куда отправляется токен | только в API брокера | в заголовке `Authorization: Bearer` с каждым запросом |
| У кого ещё есть токен | ни у кого | у Т-Банка, который его и выдал |
| Лимиты риска | ваши, в `config.toml` | на стороне брокера, настроить нельзя |
| Как выставляется заявка | черновик → сверка со свежей котировкой → отправка | сразу при вызове инструмента |
| Песочница | есть | нет |
| Новости и идеи рядом с торговлей | нет, намеренно | есть: новости, настроения рынка, инвестидеи |
| Переводы денег | сервер их не использует | есть отдельное право токена и инструмент |
| Claude Desktop | работает | не поддерживается: нет streamable HTTP |
| Установка | Python, около 10 минут | одна команда |
| Обновления | ставите сами | делает Т-Банк |
| Поддержка | сообщество, по мере сил | официальная |
| Журнал действий | локальный файл JSONL | на стороне брокера |
| Исходный код | открыт, лицензия MIT | закрыт |

## Когда лучше официальный T-Invest MCP

* Вы хотите, чтобы всё заработало одной командой и без Python.
* Вам нужна официальная поддержка и тот, кто отвечает за работу сервиса.
* Вам нужны возможности, которых в tinvest-mcp нет специально: новости с
  оценкой настроений, инвестидеи, необычные изменения в прогнозах аналитиков,
  налоговые отчёты, пополнение счёта.
* Вы не готовы следить за обновлениями. Сервер на своём компьютере, который
  давно никто не обновлял, хуже облачного, за которым следит банк. Это честный
  аргумент в пользу официального варианта.

## Когда лучше tinvest-mcp

* Вы хотите, чтобы токен оставался на вашем компьютере и не лежал в настройках
  редактора.
* Вы хотите сами задать жёсткие лимиты: сумму заявки, дневной оборот, долю
  одной позиции, список разрешённых бумаг.
* Вы хотите сначала потренироваться в песочнице на ненастоящих деньгах.
* Вы не хотите, чтобы текст из интернета — новости, идеи — попадал к модели
  вместе с инструментами для сделок.
* Вы пользуетесь Claude Desktop: к серверу на streamable HTTP он подключиться
  не может.
* Вы хотите сами прочитать код, который выставляет ваши заявки.

## Чем они отличаются с точки зрения безопасности

### Перехват в сети — не главное

Первое, что обычно тревожит в облачном MCP-сервере: «токен уходит в интернет,
вдруг его перехватят». Но оба сервера передают токен по TLS, то есть в
зашифрованном виде. Посторонний увидит адрес сервера, IP и размер пакетов, но не
сам токен. Здесь tinvest-mcp защищён не лучше и не хуже официального сервера.

Настоящая разница в двух других вещах.

### 1. Где лежит токен

Для официального сервера токен прописывают в настройках MCP-клиента: в
`.vscode/mcp.json`, `~/.qwen/settings.json` или в команде
`claude mcp add --header`. С такими файлами часто случается следующее:

* они лежат в папке проекта и **попадают в git**;
* редактор **синхронизирует их между устройствами**;
* ими **делятся с коллегами** вместе с настройками проекта;
* они мелькают на скриншотах и в сообщениях об ошибках.

Случайно закоммитить токен в репозиторий гораздо проще, чем перехватить
зашифрованное соединение. tinvest-mcp берёт токен из `.env`: этот файл
исключён из git, закрыт правами `chmod 600` и может лежать вообще вне проекта,
в `~/.config/tinvest-mcp/.env`. Так в настройках клиента секретов нет совсем.

**Справедливости ради:** токен официального сервера получает сам Т-Банк, то
есть тот, кто его выдал. Лишнего посредника здесь нет. Если бы токен брокера
забирал MCP-сервер какой-то посторонней компании, это было бы гораздо хуже.
Здесь не тот случай.

### 2. Что оказывается рядом с инструментами для сделок

Официальный сервер отдаёт модели новости с оценкой настроений, инвестидеи и
сигналы по прогнозам аналитиков. Всё это текст из интернета, который никто не
проверял. И он попадает к модели в той же сессии, где есть инструменты для
заявок и пополнения счёта. Это классическая схема prompt injection: в тексте
спрятана команда, модель её прочитала — и у неё под рукой есть кнопка «купить».

В tinvest-mcp нет ни новостей, ни оценок настроений, ни доступа в интернет. Это
не упущение, а сознательное решение. Мнение аналитиков сервер получает только в
одном месте — в `get_instrument_forecast`, и то в виде чисел: рейтинг, целевая
цена, потенциал роста в процентах. Свободного текста там нет.

Важная оговорка: мы отвечаем только за свои инструменты, а не за всю вашу
сессию. Если подключить рядом другой MCP-сервер с доступом в интернет, та же
уязвимая схема соберётся уже в вашем клиенте.

### 3. Права токена и лимиты

Права токена в Т-Инвестициях задаются грубо: только чтение, полный доступ или
полный доступ с переводами. Выбрать их можно один раз, при выпуске. Лимитов на
размер или частоту заявок, которые настраивал бы сам пользователь, в
документации официального сервера нет.

Токен в tinvest-mcp тот же самый, брокерский, с теми же правами. Но поверх него
сервер добавляет ограничения, которые задаёте вы: сумма заявки, дневной оборот,
доля позиции, отклонение цены, возраст котировки, только лимитные заявки, без
плеча и шортов, при желании — строгий список разрешённых бумаг. Для реального
счёта по умолчанию стоит всего 1 500 ₽ на заявку, чтобы первая ошибка обошлась
дёшево.

Самая надёжная защита возможна в обоих вариантах, но удобна только в
tinvest-mcp: **работать с токеном только для чтения и вообще не давать серверу
токен на сделки.** Тогда выставить заявку физически нечем, а анализ портфеля
работает как обычно. С официальным сервером можно сделать то же самое, но
торговые инструменты никуда не исчезнут — они просто будут возвращать ошибку.

### В чём tinvest-mcp уступает

Чтобы сравнение было честным:

* **Обслуживать приходится больше.** Нужно следить и за Python-окружением, и за
  самим сервером. Если давно не обновлять зависимости, это хуже, чем облачный
  сервис, который обновляет банк.
* **Сервер не знает, кто вызвал инструмент, — у официального так же.** Протокол
  MCP не сообщает, пришёл вызов от модели или от человека, который нажал
  «Подтвердить». Поэтому правило «агент не должен сам вызывать `post_order`» у
  нас — это инструкция в промпте, а не техническая блокировка. Подробнее — в
  [security.ru.md](security.ru.md).
* **Слабое место — ваш компьютер.** Токен хранится на диске. Облачная схема
  хотя бы не оставляет файл с ключом на ноутбуке, который могут украсть. Правда,
  она кладёт ключ в настройки редактора, а это обычно ещё хуже.
* **Мы добавляем доверие к российскому национальному удостоверяющему центру**
  для gRPC-соединений, иначе API Т-Банка недоступен. Это касается только
  процесса tinvest-mcp, а не системы в целом ([подробнее](security.ru.md)), но
  всё равно расширяет круг доверия — облачному серверу это на вашем компьютере
  не нужно.
* **Официальной поддержки нет.** Если что-то сломается в 9:55 перед открытием
  биржи, разбираться придётся самостоятельно, по исходному коду.

## Можно пользоваться обоими

Одно другому не мешает. Если хочется и широты официального сервера, и
осторожности tinvest-mcp в сделках, можно разделить так:

* официальный T-Invest MCP с токеном **только для чтения** — для новостей и
  идей;
* tinvest-mcp с токеном только для чтения — для работы с портфелем, а сделки
  включать лишь тогда, когда вы действительно собираетесь торговать.

Одно предупреждение. Если подключить оба сервера в одной сессии, новости
официального сервера и торговые инструменты tinvest-mcp окажутся у модели
одновременно, и уязвимая схема из раздела выше вернётся. Если это важно,
запускайте их в разных сессиях.
