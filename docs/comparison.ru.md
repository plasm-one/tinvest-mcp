# T-Invest MCP от Т-Банка и tinvest-mcp: сравнение MCP-серверов Т-Инвестиций

У Т-Банка есть официальный MCP-сервер Т-Инвестиций — **T-Invest MCP**
(<https://developer.tbank.ru/invest/mcp>). Он позволяет подключить ИИ-агента
(Claude Code, Cursor, Qwen Code, Gemini CLI, VS Code) к брокерскому счёту.
**tinvest-mcp** — неофициальная open-source альтернатива, которая решает ту же
задачу по-другому: работает локально, на вашем компьютере. Здесь честно
разобрано, чем они отличаются и когда лучше выбрать официальный сервер.

Мы не нейтральны — один из двух серверов написали мы. Поэтому текст написан так,
чтобы его можно было проверить: факты об их продукте взяты из публичной
документации, факты о нашем ссылаются на файлы, которые их реализуют.

## Коротко

| | **tinvest-mcp** (этот) | **T-Invest MCP (Т-Банк)** |
|---|---|---|
| Где работает | на вашем компьютере | на серверах Т-Банка |
| Транспорт | stdio (нет открытого порта) | streamable HTTP |
| Адрес | — | `https://invest-public-api.tbank.ru/mcp` |
| Где хранится токен | `.env`, один локальный файл | конфиг вашего MCP-клиента |
| Куда уходит токен | только в API брокера | заголовок `Authorization: Bearer` в каждом запросе к их шлюзу |
| У кого ещё есть токен | ни у кого | у Т-Банка (он его и выпустил) |
| Риск-лимиты | ваши, в `config.toml` | на стороне брокера, не настраиваются |
| Выставление заявки | превью → перепроверка по свежей котировке → отправка по id | вызов тула сразу выставляет заявку |
| Песочница | есть | нет |
| Недоверенный контент среди тулов | нет, осознанно | новости, сентимент, инвестидеи |
| Переводы денег | никогда не вызываются | доступны как скоуп токена и тул |
| Claude Desktop | работает | не поддерживается (нет streamable HTTP) |
| Установка | Python, ~10 минут | одна команда |
| Обновления | обновляете вы | обновляет Т-Банк |
| Поддержка | сообщество, по возможности | официальная |
| Журнал аудита | локальный JSONL только на добавление | на стороне брокера |
| Исходный код | MIT, можно проверить | закрыт |

## Берите официальный T-Invest MCP, если…

* Нужно, чтобы всё заработало одной командой, без Python.
* Нужен продукт с поддержкой вендора и кем-то, кто отвечает за доступность.
* Нужны инструменты, которых у нас осознанно нет: новости с оценкой сентимента,
  инвестидеи, аномалии в прогнозах инвестдомов, налоговая отчётность,
  пополнение счёта.
* Вы не собираетесь поддерживать self-hosted сервис. Заброшенный self-hosted
  сервис хуже поддерживаемого облачного — это реальный аргумент, и мы не будем
  делать вид, что это не так.

## Берите tinvest-mcp, если…

* Хотите, чтобы токен оставался на вашем компьютере и не попадал в конфиг
  редактора.
* Хотите сами задать жёсткие лимиты: сумма заявки, дневной оборот, вес позиции,
  список разрешённых инструментов.
* Хотите сначала поучиться в песочнице, пока ничего не стало настоящим.
* Хотите, чтобы недоверенного текста (новостей, идей) **не было** в одном
  контексте с торговыми инструментами.
* Пользуетесь Claude Desktop, который не подключается к streamable-HTTP серверу.
* Хотите прочитать код, который выставляет ваши заявки.

## Разница в безопасности

### Дело не в передаче по сети

Интуитивное опасение насчёт облачного MCP-сервера — «токен уходит по сети, его
могут перехватить». Если точнее: **оба варианта передают токен по TLS, и в обоих
он зашифрован в канале.** Наблюдатель видит хост назначения (SNI), IP и размеры
пакетов, но не токен. gRPC-канал этого сервера защищён ровно так же, как их
HTTPS-запрос.

Разница в другом — в двух вещах.

### 1. Где токен лежит

В их схеме токен кладётся в конфиг MCP-клиента — `.vscode/mcp.json`,
`~/.qwen/settings.json`, вызов `claude mcp add --header`. Эти файлы:

* лежат внутри проектов и **попадают в git**;
* **синхронизируются между машинами** через синхронизацию настроек редактора;
* **передаются в команде** как часть настройки проекта;
* попадают на скриншоты и в баг-репорты.

Токен, закоммиченный в репозиторий, — гораздо более вероятный инцидент, чем
атака на TLS. Этот сервер читает токен из `.env` — он в `.gitignore`, с правами
`chmod 600` и может лежать вне любого репозитория в
`~/.config/tinvest-mcp/.env` — именно для того, чтобы конфиг клиента оставался
без секретов.

**Справедливости ради:** получатель их токена — Т-Банк, тот, кто его выпустил.
Новая доверенная сторона не появляется. Если бы MCP-сервер, принимающий токен
брокера, размещала *третья сторона*, это была бы принципиально другая и куда
более плохая ситуация. У них не так.

### 2. Что находится рядом с торговыми инструментами

Их сервер отдаёт новости с оценкой сентимента, инвестидеи и аномалии в
прогнозах инвестдомов — **недоверенный текст из интернета** — в той же сессии,
что и тулы, которые выставляют заявки и пополняют счёт. Это классическая
цепочка prompt injection: текст, который читает модель, пытается ею управлять, а
у модели в руках исполнительные механизмы.

У этого сервера **нет новостей, сентимента и веб-запросов**. Это осознанное
решение, а не недостающая функция. Единственное место, где появляется чужое
мнение (`get_instrument_forecast`), возвращает структурированные числовые поля —
рейтинг, целевую цену, потенциал в процентах — а не текст.

Оговорка: мы контролируем набор своих тулов, а не вашу сессию. Подключите рядом
MCP-сервер с доступом в интернет — и вы соберёте ту же цепочку в своём клиенте.

### 3. Скоупы и лимиты

Скоупы токена у Т-Банка грубые — только чтение, полный доступ или полный доступ
плюс переводы — и выбираются один раз при выпуске. Настраиваемых
пользователем лимитов на размер или частоту заявок в документации нет.

Здесь выбор скоупа тот же (токен в любом случае брокерский), но сервер добавляет
лимиты под вашим контролем: сумма заявки, дневной оборот, вес позиции,
отклонение цены, возраст котировки, только LIMIT, без маржи, без шортов и
опциональный строгий список разрешённых инструментов. Продовые значения по
умолчанию намеренно крошечные — 1 500 ₽ на заявку, — чтобы первая ошибка стала
дешёвым уроком.

И главная мера доступна в обеих архитектурах, но удобна только в этой:
**работать с read-only токеном и вообще без токена на исполнение.** Здесь это
делает заявки структурно невозможными, а ресёрч продолжает работать. На
облачном сервере с фиксированным списком тулов аналог — выпустить read-only
токен и смириться с тем, что торговые тулы будут просто падать с ошибкой.

### Где этот сервер слабее

Для честности:

* **Поддерживать нужно две вещи, а не одну**: окружение Python и сам сервер.
  Устаревший self-hosted сервер с непропатченной зависимостью хуже управляемого.
* **Нет идентичности вызывающего — как и у них.** MCP не сообщает серверу, пришёл
  вызов от модели или от человека, нажавшего «Подтвердить». Наше «агент не должен
  вызывать `post_order`» — это инструкция в промпте, а не гейт, см.
  [security.ru.md](security.ru.md). У их сервера то же структурное свойство.
* **Слабое место — ваш компьютер.** Токен лежит на диске. Облачная схема хотя бы
  не кладёт долгоживущий файл с ключом на ноутбук, который могут украсть —
  правда, кладёт его в конфиг редактора, что обычно хуже.
* **Мы расширяем доверие TLS** на российский национальный УЦ для gRPC-каналов
  этого процесса, иначе API недоступен. Это ограничено одним процессом, а не
  системным хранилищем сертификатов ([подробнее](security.ru.md)), но всё равно
  расширение доверия, которого облачный клиент локально не требует.
* **Нет официальной поддержки.** Если что-то сломается в 9:55 перед открытием
  торгов, разбираться придётся по нашему исходному коду.

## Можно использовать оба

Ничто не мешает. Разумное разделение, если нужна широта их ресёрча и
дисциплина исполнения этого сервера:

* Официальный T-Invest MCP с **read-only** токеном — для новостей и идей.
* tinvest-mcp с read-only токеном — для работы с портфелем, а исполнение
  включать только тогда, когда вы осознанно торгуете.

Одно предупреждение: если оба сервера подключены в одной сессии клиента, их
новостные тулы и наши торговые оказываются в одном контексте, и цепочка
prompt injection, которой этот сервер избегает, собирается заново. Если это
важно, держите их в разных сессиях.
